# Hold / SkyArea 物量反推：五谱拟合与未确定项（0.5）

## 结论先行

找到能同时匹配五份谱面所有分类总量的简单候选；不是把每条Hold/Sky记成1，也不合并相同group。**但还不能唯一确定原游戏计数公式、tick时刻和中途score算法。** 已构造不同公式，它们在这五份数据的每条持续音符上也给相同数目，因而不是“更多遍历同一批数据”就能解决的歧义。

输入：用户Notes.zip中的五份明文，以及Enigma Minimal 36秒全Exact录屏。没有运行游戏内核，没有OCR，也没有把视频开始当作歌曲零点。

## 候选A（代码当前采用的临时模型）

定义B为音符开始位置的正BPM，D为持续毫秒：

```
Δ = ceil(30000 / B)
Tap = 1
Flick = 1
Hold = max(2, ceil(D / Δ) + 1)
SkyArea = max(1, ceil((D - 1) / Δ))
```

每条持续对象使用一个毫秒整数半拍步长。举例：172 BPM时Δ=175ms；348或349ms Hold皆为3；1308ms Sky为8。200 BPM时Δ=150ms。公式中的最小值与端点政策同样是临时选择，零长/极短事件没有被全部样本证明。

**为什么不能直接宣称精确公式？** Hold改为 `max(2,ceil((D-1)/Δ)+1)` 在全部输入上也吻合。更不同的一组候选B也吻合：

```
Hold_B = max(2, floor((D+0.5)*B/30000 + 0.5) + 1)
Sky_B  = max(1, floor((D+60)*B/30000 + 0.5))
```

B不是推荐的游戏模型，其作用是反证“分类总量全中便唯一确定公式”的说法。脚本验证：A/B在五份谱面中连逐对象数目都相同。规则选择不能依靠美化术语或无依据的确信。

## BPM变化尚未验证

## 最小区分实验

建议用120 BPM、4拍，孤立一个音符，等待结束后读稳定最终连击（开头的零连击到该音符结束后的增量）。

| 语句 | 候选A | 候选B | 目的 |
|---|---:|---:|---|
| hold(1000,1,1,251) | 3 | 2 | 半拍边界+1ms；也区分Hold是否扣1ms |
| skyarea(1000,50,100,20,50,100,20,0,0,252) | 2 | 1 | Sky越过候选步长时的端点政策 |

为了避免原游戏对孤立极短段另有例外，Fixtures里还给出同位置D=250/251/252的单事件独立谱，不把它们同时间叠起来。测一次的连击增量要对应唯一一个事件。

第二组实验专门改变中途BPM：起点1000、持续3000、bpm(2500,240,4)，初始120。一个Hold或一个Sky跨越该变化，与整个120 BPM的对照谱比较。若出现大于取整误差的连击差，即可排除纯起点BPM模型；若相同，还需要更多时长/变化点确认，不能一次相同就当定律。

所有实验都只是明文SPC规格。本包未实现官方ICP1二进制写出；只有在你的现有本体加载流程支持时才可直接使用。否则需要从原曲寻找这些长度/变BPM的可分离片段。**不要把在本编辑器中播放候选模型当成原游戏实验。**

## 实现信任级别

`MEASURED REFERENCE MATCH`：当前已知note/BPM语义与用户给定参考匹配，可展示已测总数及按用户上限式的MAX；不等于内部tick全解明。

`PROVISIONAL COUNT`：新谱只展示候选分类数；不给未经验证的MAX或中途分数。

`RECORDED`：可回放已有用户score记录，按原有原始字节hash失效机制，与候选计数和可视指针的时间窗完全隔离。

下一步最有信息量的材料不是同一常见拍长的另一整谱，而是上述边界样例和真实变BPM样例的稳定连击增量。
