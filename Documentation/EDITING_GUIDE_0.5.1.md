# InFalsus Studio 0.5.1 — 手动保存、可对照物量、直觉缓动把手

适用基线：用户已经在 Unity 6000.3.24f1 验收的 0.5。新增代码仍需在该环境编译和运行验收；交付环境未运行 C# 或 Unity。

## 1. 安装
先在旧版保存需要保留的谱面，停止 Unity Play、关闭 Unity，备份工程和歌曲目录。把更新包的 `Assets` 合并到工程根目录，同名替换并保留 `.meta`；不用删除旧目录，不使用旧 `.unitypackage`，不改 Packages/ProjectSettings。重新打开 Demo，进入 Play，顶部应显示 `UNITY EDITOR 0.5.1`。

完整源码包用于备份或新工程。它不是可以直接加入 Unity Hub 的完整工程：新用户先创建 URP 工程，再合并 Assets。更新包与完整包只选一个安装。

## 2. 现在只有明确保存才写入项目文件

| 操作 | 结果 |
|---|---|
| 曲名／曲师／标级输入后按 Enter、OK 或 Apply | 更新内存与画面，不写 `song.json` 或工程文件 |
| 添加、删除、移动音符；原始语句 Apply；撤销／重做 | 只更新内存谱面 |
| 切换难度 | 保留各难度内存谱面与撤销历史，不保存 |
| 顶部 `Save project`、Song 面板保存按钮、Ctrl+S | 保存全部有改动的难度、歌曲元数据、音频偏移和待保存的实测物量 |
| Save As / Ctrl+Shift+S | 导出当前谱面副本，不代表原工程已保存，也不清除原工程的脏标记 |
| 停止 Unity Play／关闭而没有保存 | 放弃本会话未保存的修改；下次打开读取上次保存结果 |
| 主动打开另一首歌／加载另一谱／New | 有修改时询问 Save / Cancel / Discard；Discard 不写文件 |

星号 `* unsaved` 表示内存修改尚未落盘。文件夹工程的 Save 是**整个歌曲工程保存**，不是只保存当前难度；避免在 FBD 改完切到 MIN 后，遗漏 FBD 的编辑。

在曲名／曲师／等级输入框尚未退出时，Ctrl+S 会先验证并接收该输入，再执行保存。原始谱面 SOURCE／numeric 文本仍需先 Apply 才进入文档；未 Apply 的草稿文字不属于已提交谱面。

不再在切难度、定时器或 OnDestroy 中保存／写恢复副本。旧版本留下的 Recovery 文件不会被删除，也不会自动回填。请明确保存后再停止 Play。初次打开只有音乐的新文件夹仍会创建默认 100 BPM、4 拍的工程，这属于你授权的新建流程；音频缓存也仍会由 Unity 导入。

### 保存位置与失败保护

工作谱仍在 `.ifstudio/Charts/0_Minimal.spc` 至 `3_Forbidden.spc`。工程元数据写 `infalsus.studio.json`；存在受支持的来源 `song.json` 时，显式保存才同步曲名、曲师和当前各难度等级对应字段。不会改写来源二进制 SPC、JSON 谱面、音频或曲绘。

来源 JSON 只替换相应标量 token，保留无关字段、超大整数、BOM、换行等。保存前比较打开／上次保存时的文件字节，拒绝无声覆盖外部修改。批次失败保留内存未保存状态，并尝试回滚已经替换、且未被其他程序修改的文件。

每次实际保存才在 `.ifstudio/SaveHistory/` 生成 before/after 和路径清单，旧目标还有 `.bak`。这提供正常写入失败后的恢复能力，**不是多文件跨进程崩溃／断电原子事务**。保存失败请保留提示中的备份路径，不要直接关闭带星号的工程。

## 3. 预计物量现在可以按时间对照

左上 SCORE 底框内显示 `EST. COMBO 当前 / 全曲`；原分数算法没有被猜测。Song 面板同时显示当前时间、Tap/Hold/Sky/Flick 四类累计量、全曲候选分类总量；选中单个物件后 Inspector 显示 `EST ticks 已发生 / 该物件总量`、开始 BPM、候选间隔与下一个候选判定时刻。

数据来自原始谱面时间，不来自画面里同时间 Flick 的可视扫动延迟。播放、暂停、倒回和 Seek 都从目标时间重算，不积累上次运行状态。

当前默认模型 A：

```
B = 音符开始时所在 BPM 段的正 BPM
Δ = ceil(30000 / B) 毫秒
Tap = 1
Flick = 1
Hold = max(2, ceil(D / Δ) + 1)
SkyArea = max(1, ceil((D - 1) / Δ))
```

这些总量在五份参考谱的各类型统计全部吻合，但不能证明逐 tick 时刻与跨 BPM 行为唯一正确。本版进一步**暂定**：Hold 为头、内部每 Δ 毫秒、尾；Sky 为从头起每 Δ 毫秒，达到候选数后停止。例：172 BPM、349ms Hold，暂定头／+175ms／尾三次。真变 BPM 时，跨段长条暂时继续使用起点 BPM，后续新音符使用它自己的起点 BPM，并显示未验证提示。

遇到未知／非法谱面字段导致无法完整计数时，不把不完整结果伪装成完整物量。SCORE 仍是未知或已有实测回放，不将候选物量直接当成已解明的分数公式。

### 如何提供有效的反例

关闭节拍网格即可用 Go 定位任意毫秒；网格开着会按既有规则吸附播放头。暂停在对照时间，打开 Song → `Export count report at playhead...`，选择歌曲目录外的诊断路径。报告含谱面哈希、时间、各类型当前数、各物件 SourceId/头尾/开始 BPM/间隔/候选总量/当前量/下一时刻。导出报告不是保存工程。

对照时同时提供原游戏连击数、歌曲时间（不是视频自带时间）、谱面副本与游戏版本。界面上的显示延迟可能产生几帧差异；某条长条结束后的稳定连击增量通常更易排查。实测总物量输入仍是明确测量，不用物件记录数替代；修改实测数也要 Save 才落盘。

## 4. 你观察到的减速确实存在，但这两处是 track

详细原文审计见 `TIMING_AUDIT_0.5.1.md` 与 `Reference/timing_audit_051.json`。

- Enigma FBD：`chart(172,4)`；785ms 开始滚速递降，1395ms 到 `track(...,0.25)`，22326ms 到0.1，22674ms 到2.0，然后逐步回1.0。提供的该谱没有 bpm 语句。
- Lights Out FBD：`chart(130,4)`；22154ms 的两条 Hold 持续3231ms，滚速从0.3逐步加至25385ms的1.0。该谱没有 bpm 语句。

`bpm` 负责节拍和当前候选物量的间隔；`track` 负责视觉位移。变慢／变快的观察是正确的，但不能单凭下落速度判断 BPM 数值改变。此处模型给 Lights Out 两条 Hold 各15，总计30；Δ=231ms，不乘0.3等滚速。

## 5. 缓动把手按曲线实际凹凸移动

继续按住**左 Ctrl**才允许主体与把手拖动。L~/R~现在按该边界的首尾X差动态映射，向屏幕左拖，边界中段就向左；向右拖，就向右。不再固定“左侧向外=Out、向里=In”。

| 边界自身 X 变化 | 向左拖中段 | 中间档 | 向右拖中段 |
|---|---|---|---|
| 起点 X < 终点 X | SineIn | Linear | SineOut |
| 起点 X > 终点 X | SineOut | Linear | SineIn |

左右两侧都用这张表；外凸／内凹由实际边界移动方向决定。只改对应一侧缓动码，不改端点、时间、宽度、另一侧缓动或 group。抓住已有曲线时不会跳回 Linear，一次拖动一次撤销。

### 贴边与等X直线要区别

每次选择／拖动重新读当前端点，不保留“曾经靠边所以永久锁住”的状态。只有该边界的首尾都等于0或都等于100，才显示 `[wall]`；另一侧独立。新建或显式编辑缓动时，贴墙那侧采用Linear。

首尾 X 相同、但不在墙上的边界显示 `[=X]`，不是硬边界锁定。**整条平移后，两端X仍相同，因此任意 easing 都仍是直线。** 把 H/T 或某一端边界移开，使该侧两端X不同，中段把手会立即恢复。原生SPC只有端点＋三种缓动，没有任意控制点；不会为了看起来“能弯”而偷偷改宽度、端点或生成新事件。

导入／原始SOURCE输入仍保留原文，不因为显示锁定就自动清洗所有旧 easing 码。
