# InFalsus Studio 0.3.1 操作与修补手册

本版在已运行的0.3上增量修改。新增源码在交付环境未执行 C# 编译、Unity 导入或实际键鼠测试；独立数学、静态和更新包检查不代替这些验收。

## 1. 安装

保存工作副本 → 停止 Unity Play → 关闭 Unity并备份 → 更新包 Assets 合并至工程根 → 同名覆盖、保留meta → 打开工程等编译 → Tools / InFalsus Studio / Open Demo Scene → Play。
顶部应显示 **UNITY EDITOR 0.3.1**。不用删除原文件夹、Library、Packages，不使用旧unitypackage。
自定义素材和用户音频目录不在此补丁的删除范围；补丁不执行任何删除。

## 2. 滚轮与播放头

鼠标在三维场地或底部详细时间轴上，向上滚前进、向下滚后退。一档移动到下一条/上一条**当前细分的实际网格线**，不再固定加半拍，也不再按屏幕跨度加毫秒。
同一时刻的 `1/4 beat`、`1/6 beat`、`1/8 beat` 分别为每拍4、6、8格。130 BPM /4，从零向上四档得到：115、231、346、462ms。
在底部详细时间轴，Ctrl+滚轮仍然是缩放时间视野，不是移动播放头；普通滚轮按拍格导航。滚轮在Inspector/Calibration等滚动面板上，仍然滚动面板，不穿透去改播放头。

### 播放头锁网格的边界

开启 Beat grid (snap) 且**处于暂停/编辑状态**，拖播放头、输入Go、切换细分或预设后都会落在最近网格。画面上的判定线固定，实际是把谱面浏览时间移动到该网格相遇的位置，不移动相机或判定面。
播放音乐时必须连续走时，不能阶梯式跳格；播放过程中滚轮会先暂停，再按方向找下一个格。原有音符时间不因播放头吸附而改写。
关闭网格后可用Go/滑条精确查看任意时间；滚轮仍按当前细分逐格导航。
因此开启网格时，Opening ~1826 可能落到1846；需要旧版精确截图时间，先关闭网格再点预设。手工编辑SOURCE语句的时间仍不强制取整。

### 不同鼠标后端

运行时默认按3个IMGUI滚轮单位/档转换，带小数余量累积。输入单位不是拍数。
Calibration 中增加 `Input units per detent` 的1/3切换及最近原始增量显示。
若本机一档报告delta=-1，选择1；一档报告-3，选择3。正数对应向下。
这是设备刻度适配，不能把 -3 当成三拍或半拍乘数。Ctrl滚轮的时间视野缩放另行处理。

## 3. 更明显的网格

小节线：蓝色，3.5px；整拍：红/绿交替，2.5px；细分线：浅青色，1.65px。像素宽度相对于Game渲染分辨率，不是固定世界厚度。
每个时间点只求值一次，使用相同Z分别绘制六轨的横截面，侧轨部分自然沿斜面倾斜，不另算一套拍点。
鼠标悬停的黄线复用同一组轨道中心线坐标；网格线在播放头处与原场地判定线使用相同的绘制抬升约定。
远处仍有原有雾效果；极密集网格在地平线附近会压在一起，但不会人为只留下每几条。停流/倒流造成多个时间恰好在同一Z时，绘制一条优先级最高的线，避免叠加数百层。时间候选数据不被删除。

### BPM timing与track的区别

`chart(bpm,beatsPerBar)` 确定起始段；每条有效正BPM的 `bpm(time,bpm,beatsPerBar)` 从其 time 重新开始局部细分拍和小节。
省略beatsPerBar继承上一有效值；同一时间后出现的BPM行优先。track只改变滚动积分，不重置音乐拍点。
例如 `chart(120,4)` 加 `bpm(1123,150,3)`：新段从1123开始，/4的前几个落点是1123、1223、1323、1423……；新段小节从1123、2323……开始。不是沿全曲0ms的旧网格继续累加。

时间计算：`round(段起点 + 格号 * 60000 / BPM / 细分数)`，先算绝对落点，最后只取整一次。
小节计算：`round(段起点 + 小节号 * 每小节拍数 * 60000 / BPM)`。
不能先把一格115.3846取整成115，再反复加115。对原始文档也不执行全局格式化。
非正BPM仍为保留/未解释路径，不声称支持游戏全部特殊timing语义。

## 4. 右键立即显示

右键按下即显示当前Home或Point菜单，不再显示“继续按住右键”提示，也没有首层0.28秒门限。
按钮上松开右键才执行；空白处松开不改变任何模式/工具/默认值，左键不用于菜单确认。
Tap/Hold/Flick悬停0.5秒打开对应子菜单的规则不变，整个过程右键一直按住，子菜单以原类型按钮为中心。此0.5秒不是首层开菜单延迟。
点立得模式下工具持续生效；不创建停用工具但保留模式，退出同时停用工具并回Home。

## 5. SkyArea中段缓动把手

先选中Sky，按住**左Ctrl**。左右边界在原始 `(startTime+endTime)/2` 位置各增加一个把手：`L~`、`R~`。这是原始时间中点，不是裁剪后可见部分的中点，也不一定是透视屏幕长度的一半。
按住左鼠标拖该把手：向外选择SineOut，回到中间区域选择Linear，向内选择SineIn。
左侧的外是屏幕左，右侧的外是屏幕右。拖动时出现固定的三挡小标尺，中央有容差带。抓住已有Out/In时保持当前档位，不会一按下就跳成Linear。
只改变本段左/右缓动字段arg7/arg8，不改变首尾时间、中心、宽度、split、group或其他段。
松开左鼠标，或先松开左Ctrl，提交一次；Esc/失焦取消。一次拖动只有一个撤销记录。

缓动仍是SPC支持的三个枚举，不是新增任意曲率数值。某侧首尾X完全相同，改变该侧缓动不会造成可见弯曲，这是数学上的正常结果；两侧都不变的直条不能仅靠改ease变成鼓起的曲线。
Out/In的视觉凸凹还受首尾位移方向影响；这里约定“向外/向内”为选择操作的方向，不改变原本的正弦定义。

## 6. 宽地键自动向左让位

下表是新建Tap/Hold时的实际起始lane：

| 默认宽度 | 点击1 | 点击2 | 点击3 | 点击4 |
|---|---:|---:|---:|---:|
| 1 | 1 | 2 | 3 | 4 |
| 2 | 1 | 2 | 3 | 3 |
| 3 | 1 | 2 | 2 | 2 |
| 4 | 1 | 1 | 1 | 1 |

宽度始终不缩水。例如宽3点击3或4，写成从2开始覆盖234；宽4点任意中央轨，都是从1开始覆盖1234。
点击lane0/5始终单宽；不会被中央宽键刷子挤到中间。
放置预览、分步提交和Inspector Quick add使用同一个解析函数。Hold在第一步确定起始lane/width，第二步只选结束时间。
此规则只用于新建放置，不擅自改导入原文，不改变整组选区移动的相对位置。原语句中的非法覆盖仍保留并提示，不能让导入时静默“修复”。

## 7. Unity GUILayout错误的处理

0.3的Inspector直接按CurrentMs动态筛选附近音符，每轮Layout和Repaint之间可能出现不同数量；更改选择、删除、原始语句改变类型又可能在同一轮绘制改变字段/分组数量。源码中存在能触发所报错误的路径，但交付环境没有真实Unity复现。
本补丁把面板开关、主选中类型、参数数组、附近事件列表、Timing列表、诊断文本在Layout开始冻结；绘制复用快照。
会改变文档或面板结构的按钮进入队列，在下一轮Layout且没有BeginArea/BeginScrollView开启时执行。Sky数学诊断不再在绘制catch里改变控件数量，也不吞掉ExitGUIException。
这不是用try/catch隐藏整轮GUILayout报错，也不要求关闭Inspector功能。实际Unity循环仍需验收。
截图中的 `InFalsus recovery copy:` 为正常恢复副本日志，和红色GUILayout异常不是同一件事；无需删除恢复文件或重装Unity。

## 8. 最小实机验收

1. 用 `Fixtures/Grid_130_4_Verification.spc`，Go到0，分别切/4 /6 /8；检查每拍4/6/8格且六轨同相位。上下各滚12档，返回0；界面显示时间要与 `Fixtures/Grid_031_Expected.json` 对应。
2. 用 `Fixtures/Grid_Timing_Reset_031.spc` 在1123附近滚动，跨段前1000、段头1123、新段1223；检查3拍小节频率以及track不重置网格。
3. 开Inspector并播放LightsOut，让附近事件不断进出窗口；切换Sky/Tap/Timing选择，增删、Undo/Redo、切面板。确认Console无新的control-count或Invalid GUILayout state。此步骤是本次GUI修补的关键，不可只看空场。
4. 在宽度3时分别点击中央2/3/4，都应得到覆盖234；宽4点击所有中央轨都相同；侧轨单宽。
5. 用 `Fixtures/Sky_Ease_Handle_031.spc`，左Ctrl拖L~/R~来回变档，原始语句只改第8/9项（0-based arg7/8）；Undo/Redo一次还原。
6. 开启网格时暂停/Go/切细分要吸附，播放应连续；关闭网格后Go1826保持1826；手输原始小数时间仍不被强制改写。

核心检查菜单：Tools / InFalsus Studio / Run CSharp Core Checks。
它现在含NavigationSelfTests，能够验证实际C#的网格、滚轮转换、宽键和曲线枚举；不负责真实鼠标或GUILayout循环。

### 滑条边界补充

滑条仅在真实用户输入改变时Seek，不在Layout/Repaint时把超出旧谱面末端的播放头钳回非网格时间。滚轮可浏览到末尾之后，方便继续制谱；暂停锁格后Go输入框同步显示实际落点，未参与修改的原文不变。
